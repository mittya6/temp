# Spring MVC ハンズオン: @ControllerAdvice と @ExceptionHandler による共通エラーハンドリング

## 1. はじめに

これまでのハンズオンでは、Spring MVCの基本構成、Tomcat/PostgreSQLのDocker環境構築、JSPによる画面描画、MyBatisによるDBアクセス、および `HttpSession` と `HandlerInterceptor` を用いたログイン認証を実装してきました。

Webアプリケーション運用において、データベース接続エラーやプログラムのバグ（`NullPointerException`等）、存在しないリソースへのアクセスが発生した際、**デフォルトのエラー画面（スタックトレースがそのまま表示される画面）をユーザーに見せることは、セキュリティおよびUX（ユーザー体験）の観点から望ましくありません。**

本ドキュメントでは、Spring MVCが提供する **`@ControllerAdvice`** と **`@ExceptionHandler`** を活用し、アプリケーション全体で発生する例外をアスペクト指向（AOP）的に一元管理・横断処理する「共通エラーハンドリング」の実装手順を解説します。

---

## 2. 共通エラーハンドリングの概念と役割

### 従来の課題（個別処理）
* **コードの重複**: 各コントローラーで `try-catch` 文を記述すると、エラー処理コードが散乱し保守性が低下します。
* **情報漏洩リスク**: 予期せぬ例外発生時に生のスタックトレースがブラウザに表示されると、内部構造（ライブラリバージョンやDB構成）が攻撃者に露出します。

### `@ControllerAdvice` による解決
Spring MVCの `@ControllerAdvice` を使用すると、すべてのコントローラーから送出される例外を1つのクラスでキャッチできます。

```
[ クライアント (ブラウザ) ]
        │ 1. リクエスト
        ▼
[ Controller ] ── ( 2. 処理中に例外発生 ) ──┐
                                             ▼
                                 [ @ControllerAdvice ] (GlobalExceptionHandler)
                                             │ 3. 例外の捕捉・ログ出力
                                             ▼
[ エラーJSP (500.jsp / 404.jsp) ] ◄── 4. 適切なHTTPステータスと画面返却
```

## 3. 実装手順

### ステップ 1: カスタム例外クラスの作成 (`ResourceNotFoundException.java`)

特定のリソース（ユーザー情報など）が存在しない場合にスローするアプリケーション独自の例外を作成します。

```java
package com.example.exception;

// 該当するデータが見つからない場合にスローするカスタム例外
public class ResourceNotFoundException extends RuntimeException {

    public ResourceNotFoundException(String message) {
        super(message);
    }

    public ResourceNotFoundException(String message, Throwable cause) {
        super(message, cause);
    }
}
```

---

### ステップ 2: グローバル例外ハンドラクラスの実装 (`GlobalExceptionHandler.java`)

すべてのコントローラーからスローされた例外を共通で捕捉するクラスを作成します。

```java
package com.example.exception;

import jakarta.servlet.http.HttpServletResponse;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.http.HttpStatus;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.ControllerAdvice;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.ResponseStatus;

@ControllerAdvice
public class GlobalExceptionHandler {

    private static final Logger logger = LoggerFactory.getLogger(GlobalExceptionHandler.class);

    /**
     * 1. 404 Not Found 系の例外（ResourceNotFoundException）をハンドリング
     */
    @ExceptionHandler(ResourceNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND) // レスポンスのHTTPステータスを 404 に設定
    public String handleResourceNotFoundException(ResourceNotFoundException ex, Model model) {
        logger.warn("リソース未発見例外が発生しました: {}", ex.getMessage());

        model.addAttribute("errorMessage", ex.getMessage());
        model.addAttribute("status", HttpStatus.NOT_FOUND.value());
        
        // /WEB-INF/views/error/404.jsp を表示
        return "error/404";
    }

    /**
     * 2. 予期せぬシステム例外（Exception全般）をハンドリング
     */
    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR) // レスポンスのHTTPステータスを 500 に設定
    public String handleGeneralException(Exception ex, Model model) {
        // スタックトレースを含めてエラーログを出力（運用分析用）
        logger.error("予期せぬシステムエラーが発生しました", ex);

        model.addAttribute("errorMessage", "システムエラーが発生しました。管理者にお問い合わせください。");
        model.addAttribute("status", HttpStatus.INTERNAL_SERVER_ERROR.value());

        // /WEB-INF/views/error/500.jsp を表示
        return "error/500";
    }
}
```

### ステップ 3: エラー表示用JSP画面の作成

ユーザーに表示するためのエラー画面を作成します。セキュリティ保護のため、スタックトレースは表示せず、親切なメッセージのみを伝えます。

#### ① 500エラー画面 (`src/main/webapp/WEB-INF/views/error/500.jsp`)

```jsp
<%@ page contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" isErrorPage="true" %>
<%@ taglib prefix="c" uri="jakarta.tags.core" %>
<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>500 - システムエラー</title>
    <style>
        body { font-family: sans-serif; margin: 40px; background-color: #f8f9fa; }
        .error-container { background: #fff; padding: 30px; border-radius: 8px; border: 1px solid #dee2e6; max-width: 600px; }
        h1 { color: #dc3545; }
        .btn { display: inline-block; margin-top: 15px; padding: 10px 20px; background: #0d6efd; color: #fff; text-decoration: none; border-radius: 4px; }
    </style>
</head>
<body>
    <div class="error-container">
        <h1>[ステータス: ${status}] システムエラー</h1>
        <p><c:out value="${errorMessage}" /></p>
        <p>ご不便をおかけして申し訳ありません。時間をおいて再度お試しください。</p>
        
        <a href="${pageContext.request.contextPath}/main" class="btn">メイン画面へ戻る</a>
    </div>
</body>
</html>
```

### ステップ 4: 検証用コントローラーの実装 (`TestErrorController.java`)

エラーハンドリングが正常に動作するかテストするための動作確認用コントローラーを作成します。

```java
package com.example.controller;

import com.example.exception.ResourceNotFoundException;
import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;

@Controller
@RequestMapping("/test-error")
public class TestErrorController {

    // 意図的に 500 (NullPointerException) を発生させるテスト
    @GetMapping("/500")
    public String triggerServerError() {
        String nullStr = null;
        // NullPointerException が発生する
        nullStr.length();
        return "main";
    }

    // 意図的に 404 (ResourceNotFoundException) を発生させるテスト
    @GetMapping("/404")
    public String triggerNotFoundError() {
        throw new ResourceNotFoundException("指定されたID（ID: 999）のユーザーデータが存在しません。");
    }
}
```

## 4. 動作確認手順

1. **500エラーのテスト**:
   - ブラウザで `http://localhost:8080/app/test-error/500` にアクセスします。
   - `GlobalExceptionHandler` の `handleGeneralException` が起動し、画面にはスタックトレースではなく整理された `500.jsp` が表示されます。
   - サーバーログ（コンソール）には意図通りスタックトレースが出力されていることを確認します。

2. **404エラーのテスト**:
   - ブラウザで `http://localhost:8080/app/test-error/404` にアクセスします。
   - `handleResourceNotFoundException` が起動し、HTTPステータスコード `404` と共に `404.jsp` が表示されることを確認します。

## 5. まとめと次のステップ

本ハンズオンにより、Spring MVCにおける堅牢なエラーハンドリング基盤が完成しました。

* **`@ControllerAdvice`**: コントローラーレイヤー全体の例外を一元監視・インターセプトする。
* **`@ExceptionHandler`**: 対象の例外クラスごとに返却するレスポンス画面やレスポンスコードを定義する。
* **セキュリティ向上**: スタックトレースを隠蔽し、安全かつ一貫性のあるUIをユーザーに提供する。

これで「認証・認可（Interceptor）」「DBアクセス（MyBatis）」「共通エラーハンドリング（ControllerAdvice）」というWebアプリケーションの3大インフラ機能が整いました。
